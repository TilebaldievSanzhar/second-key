# ADR 0003 — Очередь задач: taskiq на Redis

Статус: принято · 15.10.2026

## Контекст

Аудит выгрузки занимает от секунд до минут (импорт, нормализация, правила, отчёт), позже
добавятся OCR счетов и LLM-фолбэк нормализации. Запросы API не должны ждать этого синхронно.
Нужны: async-воркеры, повторы, расписание (курсы НБКР ежедневно, сбор цен госзакупок еженедельно),
прогресс для интерфейса.

## Варианты

- **Celery** — стандарт, но синхронный по природе; async-код движка пришлось бы оборачивать.
- **arq** — простой и async, использовался в FEAP, но с 2025 года в режиме «только поддержка».
- **taskiq** — async-нативный, активно развивается, брокер Redis, планировщик, интеграция с FastAPI.

## Решение

taskiq + `taskiq-redis` (брокер на Redis Streams с подтверждением, результаты в Redis),
отдельные процессы `worker` и `scheduler` в compose.

## Правила задач

- Задача получает только идентификаторы; данные читает из БД и S3.
- Идемпотентность: повторный запуск задачи на тот же `run_id` пересобирает результат прогона
  (старые строки и находки удаляются в той же транзакции).
- Статус и прогресс пишутся в БД (источник правды) и публикуются в Redis-канал `run:{id}`
  для SSE; интерфейс переживает потерю события, перечитав статус.
- Ошибка задачи переводит прогон в `failed` с текстом причины для пользователя.
