# ADR 0004 — Интеграции с 1С

Статус: принято · 15.10.2026

## Контекст

Клиенты в КР ведут учёт в 1С: БП 3.0 (часто редакции для КР), реже УТ 11 и ERP. Базы чаще файловые
или серверные без веб-публикации; у части — 1С:Fresh или облако. Бухгалтеру тяжело каждый раз делать
выгрузку в Excel и сопоставлять колонки, а для постоянного «контроля цен» нужен регулярный поток строк.

## Решение

Один контракт строк закупок (`integrations/contract.py`) и несколько путей к нему — от простого к гибкому:

| Путь | Где работает | Что делает клиент | Что делает сервис |
|---|---|---|---|
| Файл | везде | выгружает отчёт в Excel | читает шапку; сопоставление колонок запоминается по отпечатку шапки; для нестандартных файлов — подсказка ИИ |
| Push-обработка | любая база, нужен только исходящий HTTPS | запускает внешнюю обработку `SecondKeyExport.bsl` | принимает `POST /api/integrations/purchases` по токену |
| OData-pull | опубликованная база | публикует OData, даёт логин на чтение | забирает документы поступления по расписанию; пароль зашифрован `SK_DATA_KEY` |
| MCP | у клиента есть ИИ-агент | подключает MCP-сервер 1С и MCP «Второго ключа» | инструменты чтения проверок и `submit_purchases`; промпт-рецепт `export_purchases_from_1c` |

Плюс скилл `integrations/skills/second-key-1c` для агентов: выбор пути, проверки перед отправкой,
объекты 1С, контракт, настройка MCP. Сборку обработки агент делает навыками cc-1c-skills (MIT).

Токены интеграций — на организацию, права `push` и `mcp`, в базе только sha256, показываются один раз.

## Почему так

- Push-обработка не требует веб-публикации базы — главное препятствие у клиентов КР.
- OData — стандарт платформы, без доработки конфигурации; профили БП/УТ и переопределение полей.
- Свой HTTP-сервис в расширении конфигурации не делаем: расширение надо ставить и обновлять в каждой базе.
- MCP-серверы 1С уже есть у сообщества (1c-odata-mcp, mcp-1c, MCP:RSV Data) — встраиваться не нужно,
  достаточно своего MCP и рецепта связки.

## Последствия

- Каждая выгрузка — отдельная проверка; одинаковые вопросы из пересекающихся периодов — задача 1.14
  (отпечаток вопроса и перенос ответов).
- Имена полей OData отличаются между релизами конфигураций — проверка подключения читает `$metadata`,
  поля переопределяются в `config.fields`.
