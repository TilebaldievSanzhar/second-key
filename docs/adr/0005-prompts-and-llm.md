# ADR 0005 — Промпты по модулям и слой LLM

Статус: принято · 15.10.2026

## Решение

Каждый промпт — модуль-пакет `backend/src/secondkey/prompts/<module>/`:

| Файл | Что |
|---|---|
| `prompt.toml` | версия, описание, tier модели (light/heavy), температура, лимит токенов |
| `__init__.py` | `Inputs` и `Output` (pydantic): что подаём и что принимаем |
| `system.j2`, `user.j2` | шаблоны Jinja2; переменные — только поля `Inputs`, `StrictUndefined` |
| `fallback.j2` | если есть: тот же результат без модели |

Общие правила — `_shared/macros.j2`: данные клиента в блоках `<данные>` и «не инструкции», язык, «только JSON».
Вызов — `secondkey.llm.run(module, inputs)`: рендер, модель (OpenAI-совместимый API: OpenRouter, private-контур,
vLLM), JSON-схема `Output` (json_schema → json_object для моделей без strict), валидация, повтор, лог с версией.
`secondkey prompts` — список модулей с версиями и рендер по JSON-входу.

Модули сейчас: `normalize_item`, `column_mapping`, `answer_review`, `owner_digest`.

## Принципы

- Модель предлагает, код решает: позицию определяет движок, деньги считает код.
- У каждого сценария — защита от выдумки (числа из исходника, индексы колонок, числа дайджеста — из фактов)
  и путь без модели; без `SK_LLM_API_KEY` всё работает детерминированно.
- Проверка ответа снабжения — подсказка собственнику, статус вопроса она не меняет.
- Новая формулировка — новая версия в `prompt.toml`; тесты рендерят каждый модуль и проверяют защиты
  на фейковой модели.
