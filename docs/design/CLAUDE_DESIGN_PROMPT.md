# Промпт для Claude Design

Вставьте текст ниже в Claude Design и приложите [FRONTEND_SPEC.md](FRONTEND_SPEC.md) — там экраны,
состояния, тексты и контракты API. Скриншоты функционального каркаса (http://localhost:5173,
`owner@demo.kg` и `asanov@demo.kg`, пароль `demo-demo-2026`) можно приложить как референс
потоков, но не визуала.

---

Спроектируй веб-приложение «Второй ключ» — B2B-сервис для строительных компаний Кыргызстана.
Компания загружает выгрузку закупок материалов из 1С, сервис находит, где она переплатила
(дороже, чем у другого поставщика в те же недели, дороже рынка, документ учтён дважды, закупку
раздробили ниже порога согласования), и раскрывает каждую сумму до строки учёта.

Принцип продукта: снабжение покупает, система проверяет, собственник решает. Два ключа к одному
сейфу: ключ 1 — объяснение снабжения, ключ 2 — решение собственника («переплата подтверждена»,
«обосновано», «ошибка учёта»). Сделай это фирменным паттерном: индикатор из двух сегментов
у каждого вопроса — в списке, в карточке, в сводке.

Пользователи:
- собственник (главный) — телефон, 2–3 минуты в день между объектами, живёт в WhatsApp;
  хочет за 10 секунд понять, сколько теряет, и решить крупные вопросы;
- бухгалтер — десктоп, загружает выгрузку 1С и подтверждает колонки;
- снабженец — телефон, видит только вопросы по своим закупкам и отвечает за минуту;
  интерфейс задаёт вопрос, а не обвиняет.

Экраны (375 px сначала, затем 1280 px): вход; сводка собственника (главная сумма «возможная
переплата», подтверждённое, ждут решения, крупнейшие вопросы, разрезы по поставщикам,
ответственным, материалам, правилам); входящие вопросы с табами и фильтрами; карточка вопроса
(заголовок-вопрос, факты, график цен позиции во времени с рынком, строки учёта, два ключа, режим
разбора «решил → следующий» с отменой); загрузка выгрузки (зона файла, сопоставление колонок
по предпросмотру, прогресс пяти стадий); «мои вопросы» снабженца с быстрыми причинами-чипами;
настройки порогов и людей. У каждого экрана — пустое, загрузочное, ошибочное и «длинное» состояние.

Визуальный язык: аудиторский документ, а не стартап. Спокойно, точно, тепло. Ориентиры —
банковская выписка, Linear, Stripe Dashboard. Деньги — главный герой: одна крупная сумма
на экран, табличные цифры, формат «8 267 401 сом». Тёплая бумажная основа, один акцент
(глубокий зелёный), возможная переплата — янтарный (внимание без тревоги), красный — только
для подтверждённой переплаты. Шрифты: Golos Text для интерфейса, IBM Plex Mono для номеров
документов. Таблицы почти без скруглений, кнопки 6 px. Без градиентов, стекла, эмодзи,
иллюстраций с человечками, сетки «три карточки с иконками», Inter по умолчанию
и восклицательных знаков. Тексты — на русском, конкретные глаголы («Разобрать вопросы»,
«Вернуть в работу»). WCAG AA, касание 44 px, цвет не единственный носитель смысла.

Отдай: дизайн-систему (токены как CSS-переменные, компоненты со состояниями: MoneyAmount, KeyPair,
FindingRow, PriceChart, EvidenceTable, StageProgress, Dropzone, ColumnMapper, AnswerComposer,
DecisionBar, EmptyState, Toast), все экраны в двух ширинах и прототип двух потоков —
«собственник разбирает вопросы с телефона» и «бухгалтер загружает выгрузку и запускает проверку».
Реализация будет на React 19 + TypeScript с обычным CSS и иконками Lucide; данные — по контрактам
API из приложенного ТЗ (деньги приходят строками-десятичными).
