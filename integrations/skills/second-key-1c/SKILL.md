# 1С → «Второй ключ»

«Второй ключ» проверяет цену каждой закупки материалов: сравнивает с другими поставщиками в те же недели,
с рынком (госзакупки КР), ищет повторы документов и дробление ниже порога согласования. Вход — строки
документов поступления из 1С, выход — вопросы с суммами возможной переплаты.

## Выбери путь

| Ситуация у клиента | Путь | Что нужно |
|---|---|---|
| Есть агент с MCP-сервером 1С (1c-odata-mcp, mcp-1c, MCP:RSV Data) | **A. Агент**: читаешь поступления через MCP 1С, отправляешь через MCP «Второго ключа» | токен «Второго ключа» с правами `mcp` и `push` |
| База на компьютере или сервере без веб-публикации | **B. Обработка**: внешняя обработка 1С шлёт строки по HTTPS | модуль `SecondKeyExport.bsl`, токен с правом `push` |
| База опубликована (веб-сервер, 1С:Fresh, облако) | **C. OData**: «Второй ключ» сам забирает поступления по расписанию | публикация OData с документом поступления и справочниками, логин на чтение |
| Ничего из этого | Выгрузка в Excel и загрузка файла в интерфейсе | отчёт «Поступление товаров и услуг» по строкам |

## A. Через MCP

1. Подключи два MCP-сервера: 1С (любой из перечисленных) и «Второй ключ»
   (`{адрес сервиса}/api/mcp/`, заголовок `Authorization: Bearer sk_…`) — пример в
   [references/mcp-setup.md](references/mcp-setup.md).
2. Возьми промпт `export_purchases_from_1c` у MCP «Второго ключа» — в нём шаги и поля.
3. Через MCP 1С найди проведённые документы поступления за период и их табличную часть «Товары».
   Имена объектов — в [references/onec-objects.md](references/onec-objects.md).
4. Собери строки по контракту [references/contract.md](references/contract.md). Наименования, цены и суммы
   не исправляй и не округляй: проверка сравнивает их как есть.
5. Проверь строки (раздел «Проверки» ниже), вызови `submit_purchases` пачками до 5000 строк,
   дождись `audit_status` = `done` и покажи `audit_summary`.

## B. Внешняя обработка

1. Возьми модуль: `GET {адрес}/api/integrations/1c/module.bsl` или файл
   `backend/src/secondkey/integrations/onec_push/SecondKeyExport.bsl` в репозитории.
2. Собери внешнюю обработку: реквизиты НачалоПериода, КонецПериода, АдресСервиса, Токен; команды
   «Выгрузить» и «ПроверитьСвязь»; модуль объекта и модуль формы — из соответствующих разделов файла.
   С навыками [cc-1c-skills](https://github.com/Nikolay-Shirokov/cc-1c-skills) (MIT): `epf-init` → форма
   (`form-add`, `form-edit`) → вставить модули → `epf-build` → `epf-validate`.
3. Для нетиповой конфигурации правь только функцию `ТекстЗапроса()`: поля результата остаются теми же
   (Дата, Номер, Поставщик, ИНН, Объект, Ответственный, СуммаВключаетНДС, Номенклатура, Единица,
   Количество, Цена, Сумма, СуммаНДС).
4. Бухгалтер запускает обработку, нажимает «Проверить связь», затем «Выгрузить».

## C. OData

1. «Администрирование → Публикация на веб-сервере», включить OData; в составе — документ поступления
   с табличной частью «Товары» и справочники из [references/onec-objects.md](references/onec-objects.md).
2. Завести пользователя 1С только с правом чтения этих объектов.
3. Во «Втором ключе»: Настройки → Подключение 1С → OData: адрес публикации, логин, пароль → «Проверить» —
   сервис сам определит профиль (БП или УТ/ERP). Расписание «ежедневно» — для постоянного контроля цен.

## Проверки перед отправкой

- дата каждой строки — внутри периода; документы проведены, не помечены на удаление;
- `qty` > 0; есть `price` или `amount`; `amount` ≈ `qty` × `price` (расхождение больше 1% — пометь, не исправляй);
- `amount` — с НДС: в БП, если у документа снят флаг «Сумма включает НДС», прибавь `СуммаНДС`;
- `supplier` — наименование контрагента, не ссылка; `responsible` — как сотрудник записан в 1С: по нему
  снабженец увидит свои вопросы;
- одна строка табличной части = одна строка выгрузки; не сворачивай одинаковую номенклатуру.

## Работа с результатами (MCP «Второго ключа»)

- `audit_summary` — главная сумма, что ждёт решения, крупнейшие вопросы, разрезы по поставщикам и людям;
- `list_questions` (status: waiting | decided | all) и `get_question` — вопрос со строками учёта;
- `price_history(sku)` — цены позиции по поставщикам и рынку.

Говори «возможная переплата» и «вопрос», а не «воровство» или «нарушение»: решение по каждому вопросу
принимает собственник после ответа снабжения.
